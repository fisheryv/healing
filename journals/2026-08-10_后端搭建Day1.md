唯一一处预期偏差：未鉴权请求返回 `200 + 空数组`（而非 `401`）。这是 PB 默认行为，**安全上等价**（数据不会泄漏），只是 HTTP 语义不同。如果前端要区分"未登录"和"无数据"，需检查 token 是否存在。

## 关键决策

1. **不用 PB env 变量建管理员**：0.39 已不支持 `PB_ADMIN_*`，改用 `pocketbase superuser upsert` 命令。
2. **users 表直接用 PB 内置**：扩展 PB 自带的 `users` collection，不新建"profiles"表，减少关联。
3. **API Rules 写在独立 migration**（`1754847040`）：与 collection 创建解耦，方便调试和重置。
4. **CORS 用 `--origins` 启动参数**：避免写 pb_hooks 启动脚本。
5. **`recoveryQuestion/Answer` 字段保留**：前端 `SignUp.jsx` 已经有这个流程，但目前答案**明文存**，后续需要在前端做哈希后再写入。
6. **索引暂时没建**：`artworks` 的 `(user, created DESC)` 和 `favorites` 的 `(user, musicId) UNIQUE` 在 migration 里用 `app.dao()` 写失败了（0.39 改名了）。**当前规模无所谓**，后续用户量大再补 SQL。
