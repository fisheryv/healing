## 关键决策

### 1. 放弃 Fly.io + Vercel，改用 Cloudflare Tunnel

- **原计划**：`BACKEND_POCKETBASE.md` 第 9.1 节，部署 PB 到 Fly.io + 前端到 Vercel
- **放弃原因**：Fly.io 和 Railway 都要绑信用卡，用户未成年无法办理
- **替代方案**：Cloudflare Tunnel（免费、不要信用卡、GitHub 登录即可）
- **原理**：本地继续跑 PB + vite，cloudflared 把 vite 的 5173 端口通过隧道暴露到公网，给一个 `*.trycloudflare.com` 的 HTTPS 域名
- **代价**：电脑要开着、域名随机（Quick Tunnel 模式）

### 2. 只给 vite 开 tunnel，不给 PB 单独开

- **一开始**给 PB (8090) 开了 tunnel，验证 API + Admin UI 能公网访问
- **后来改**成只给 vite (5173) 开 tunnel——因为 vite proxy 已经把 `/api` 和 `/_` 转发到本地 PB
- **好处**：一个 tunnel、一个域名搞定全部（前端页面 + API + Admin UI），不用改前端代码，不用配 `VITE_PB_URL`
- **架构**：`手机 → cloudflared → localhost:5173 (vite) → vite proxy → localhost:8090 (PB)`

### 3. 用 Quick Tunnel 而非 Named Tunnel

- **Quick Tunnel**：`cloudflared tunnel --url http://localhost:5173`，不用登录，随机域名
- **Named Tunnel**：要 `cloudflared login` + 自己的域名，固定域名
- **选 Quick 的原因**：用户没有域名，也不想花钱买。随机域名对答辩 demo 够用（答辩前启动不关就行）

### 4. vite.config.js 加 allowedHosts

- Vite 6+ 默认只允许 localhost 访问，tunnel 域名会被 403 拒绝
- 加 `allowedHosts: ['.trycloudflare.com']` 允许所有 trycloudflare 子域名
- 改完 config 必须**重启 vite**（HMR 不重载 config）

## 答辩时怎么启动（重要）

答辩前 5 分钟，开三个终端分别跑：

```bash
# 终端 1：启动 PocketBase
cd /Users/lingshanli/code/MTX_healing/backend
pocketbase serve --http=0.0.0.0:8090 --origins="*"

# 终端 2：启动前端
cd /Users/lingshanli/code/MTX_healing/src
pnpm dev

# 终端 3：启动 cloudflare tunnel
cloudflared tunnel --url http://localhost:5173
```

终端 3 会输出一个 `https://xxx-xxx-xxx-xxx.trycloudflare.com` 域名，**记下来**，这就是答辩演示用的公网地址。

**一键启动脚本**（可选，放 `~/start-healing.sh`）：
```bash
#!/bin/bash
cd /Users/lingshanli/code/MTX_healing
osascript -e 'tell app "Terminal" to do script "cd backend && pocketbase serve --http=0.0.0.0:8090 --origins=\"*\""'
osascript -e 'tell app "Terminal" to do script "cd src && pnpm dev"'
osascript -e 'tell app "Terminal" to do script "cloudflared tunnel --url http://localhost:5173"'
```
