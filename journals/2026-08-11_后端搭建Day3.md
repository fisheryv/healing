## 关键决策

1. **不播种默认预设**：新用户 `presets` 空起步，`DEFAULT_PRESETS` 常量删除。理由：真实后端不该塞 demo 数据，`FocusConfig` 已有空状态处理。

2. **`addArtwork` 改 async await（非乐观）**：与 `toggleFavorite`/`savePreset`/`deletePreset`/`deleteArtwork` 的乐观策略不同。原因：`addArtwork` 的调用方（`FocusSession`）保存后立即 `navigate('/gallery')`，如果乐观插入用 temp id，PB 响应后替换 id 会导致 ArtworkDetail 深链断裂。await 保证 Gallery 看到的是真实 PB 记录。代价是用户点 Save 后有 ~200-500ms 上传延迟（可接受）。

3. **`isPresetNameExist` 保持同步**：Mixer.jsx 的 `handleSave` 在同步条件里用它判断是否弹"覆盖"弹窗。改成 async 会破坏调用方。改为读本地 `presets` 镜像，PB 最终一致即可。

4. **字段映射：把 schema 里没有的字段塞进 `mix` JSON**：前端 artwork 有 `title` / `mixName` / `interruptReason` 三个字段不在 PB schema 里。直接 `JSON.stringify` 塞进 `mix` JSON 字段，`mapArtwork` 读回来。避免改 schema。

5. **`bgNoise` / `binaural` 在 preset 里存 ID，读时还原**：PB schema 用 `bgNoiseId` / `binauralId`（字符串），前端用 `{id, name}` / `{id, name, range}` 对象。`mapPreset` 用 `data.js` 的 `noiseOptions` / `binauralOptions` 查表还原。`ambient` 已经是 JSON 数组，直接用。

6. **`dataReady` flag**：区分"PB 加载中"和"真没数据"。`ArtworkDetail` 和 `Gallery` 在 `!dataReady` 时显示 loading，避免加载中闪现 not-found / empty。

7. **业务数据完全移出 localStorage**：`STORAGE_KEY` 现在只存 `onboardingSeen` / `settings`。dev 环境的旧 localStorage 数据（`healing_app_state_v1` 里的 favorites/presets/artworks）不再被读取，等于清空重来。这是预期的。

## 修掉的 Bug

### 1. favorites UNIQUE 索引没建上（Day 1 遗留）

- **症状**：e2e 测试发现同一用户重复收藏同一首曲（`musicId='m3'`）能创建多条记录，UNIQUE 约束没生效。
- **根因**：Day 1 的 `1754847030_create_favorites.js` 和 `1754847010_create_artworks.js` 用 `app.dao().db().newQuery(...)` 建索引，但 **PB 0.39 移除了 `app.dao()`**，调用抛错被 `try/catch` 静默吞掉。`sqlite3 .indexes` 确认两个索引都不存在（只有 `sqlite_autoindex_*`）。
- **修复**：新 migration `1754847050_add_indexes.js` 用 PB 0.22+ 的 `collection.indexes` 属性补建：
  ```js
  favorites.indexes = ["CREATE UNIQUE INDEX IF NOT EXISTS `idx_favorites_user_music` ON `favorites` (`user`, `musicId`)"]
  artworks.indexes = ["CREATE INDEX IF NOT EXISTS `idx_artworks_user_created` ON `artworks` (`user`, `created` DESC)"]
  ```
- **验证**：重启 PB 后 `sqlite3 .indexes` 确认两个索引都在；e2e 重复收藏返回 `validation_not_unique`。
- **教训**：`try/catch` 吞错误会掩盖 migration 失败。Day 1 journal 已经记了"索引暂时没建"，但当时没修。

### 2. store.jsx re-export 语法错误

- **症状**：vite 编译 store.jsx 返回 500：`Export 'favorites' is not defined.`
- **根因**：`import { favorites as favoritesApi }` 后，本地绑定名是 `favoritesApi`，但 re-export 写了 `export { favorites as favoritesApi }`（引用不存在的 `favorites`）。
- **修复**：改成 `export { favorites as favoritesApi, ... } from './api.js'`（直接从源模块 re-export，不需要本地绑定）。

### 老师可能问 & 怎么答

| 问题 | 简答 |
| --- | --- |
| 图片怎么存的？ | WebGL canvas `toDataURL('image/png')` 生成 base64 → 前端转 Blob → FormData 上传到 PB 的 `file` 字段（限 image/png，5MB） |
| 乐观更新失败怎么办？ | 当前只 console.warn 不回滚，下次 fetch 会用 PB 的真实数据覆盖本地。Demo 规模够用；生产化可加回滚 + 重试 |
| 并发编辑同一预设怎么办？ | PB 没有乐观锁（无 `updated` 字段），后写覆盖前写。Demo 单用户场景不会冲突 |
| 为什么 artworks 用 await 而其他用乐观？ | artworks 保存后立即跳转 Gallery，乐观插入 temp id 会导致 ArtworkDetail 深链断裂；其他操作用户留在原页面，乐观更新体验更好 |
| 收藏怎么防重复？ | PB UNIQUE 索引 `(user, musicId)`，DB 层面保证；前端 `favorites.add` catch 到 `validation_not_unique` 当成功处理（幂等） |
